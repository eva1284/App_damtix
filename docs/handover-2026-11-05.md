범위: 2026-10-26 ~ 11-05에 이 사용자와 함께 만든 SNS·영상·카탈로그·블로그·당첨자 발표 콘텐츠에서 확정된 규칙, 기준, 교훈, 도구, 현재 상태.

> 사용법: 1~2장은 작업 전에 반드시 읽는다. 3~9장은 해당 작업을 할 때 찾아 쓴다. 12장(실수 목록)과 14장(첫 행동)은 작업 시작 직전에 다시 본다.

## 1. 사용자와 일하는 방식 (최우선)

사용자는 DAMTIX(㈜팩토스퀘어)의 운영자이자 의사결정자다. 일본어·프랑스어는 모른다. 디자인 감각이 분명하고, 결과를 직접 보고 구체적으로 고쳐 달라고 한다.

**소통**
- 항상 **한국어**로, 짧고 직접적으로 답한다. 장황한 배경 설명보다 "무엇을 어디에 만들었는지 + 확인할 점"을 먼저.
- 파일 위치는 **중간 폴더를 빼지 말고 전체 경로**로 알린다(경로를 줄였다가 폴더를 못 찾은 사례). 열기 명령을 함께 준다.
- 사용자가 "텍스트로 줘/알려줘"라고 하면 파일을 만들지 말고 대화로 준다. 반대로 "문서/파일로 줘"면 파일을 만들고 경로를 준다.
- 확인하지 못한 것은 **확인하지 못했다고 명시**한다(소리를 직접 못 들음, 자동 클릭이 막혀 화면 확인을 못 함 등). 확인한 것만 "확인했다"고 쓴다.
- 보고 전에 **확대·프레임 단위로 직접 본다**. 저해상도 시트만 보고 "고쳐졌다"고 단정했다가 틀린 적이 있다.
- 사용자가 잘못을 지적하면 어느 단계에서 생겼는지 **원인을 찾아 근본부터** 고친다(증상만 덮지 않는다).
- 모르는 부분을 지어내지 않는다(위치, 매장 번호, 가격, 수치, 일본어 표현 등). 근거가 없으면 비워 두고 사용자에게 알린다.
- 사용자가 비워 둔 질문은 "알아서 하라"는 뜻이다. 추천안으로 정하고 결정 내용을 알린다.
- 일본어·프랑스어는 사용자에게 "이 표현이 자연스러우냐"고 묻지 않는다. AI가 정하고, **원어민 검수표**(일본어/프랑스어 + 한국어 뜻 + 의심 지점 ★)를 파일로 만들어 사용자가 검수자에게 전달하게 한다.

**진행 순서**
- **기획 먼저, 생성은 나중에.** 큰 작업은 기획을 설명하고 승인받은 뒤 만든다. 방향을 설명 없이 바꾸면 "지금 뭐하려는 거야"라는 반응이 나온다.
- **하나만 먼저.** 시험 컷 1개, 스타일 프레임 2장, 한 장표 등으로 보여 주고 OK 후에 확장한다.
- "먼저/하나만"은 범위 한정일 수도 순서일 수도 있다. 애매하면 보수적으로 해석하고, 필요하면 묻는다.
- 요청 범위만 바꾼다. "세럼 크기만", "중앙정렬만"이라고 하면 그것만 고친다. 다른 것은 건드리지 않는다.
- **새 버전을 만들지 말고 기존 파일에서 수정**하라는 요청이 많다(예: 캡컷 v2 안에서 행간만 수정). 이전 버전이 필요하면 `_이전버전` 폴더에 보관하되, 사용자가 이 폴더를 직접 정리할 수 있다.
- 컨텐츠 문서·카탈로그는 "있는 자료로 적당히 채우기"를 금지한다. 페이지마다 필요한 내용 칸을 먼저 기획하고 자료를 요청한다.
- 이미지 생성(크레딧)은 **비용 견적 → 생성 → 사용량 보고** 순서. 보고에 "크레딧을 썼다"고 적는다.
- 게시·업로드·전송은 **절대 하지 않는다.** 사용자가 직접 한다.

**사용자 파일 보호**
- 사용자가 직접 고친 파일(캡컷 드래프트, Figma 편집, 사용자가 편집한 PNG)은 **재생성 금지.** 읽어서 그 상태를 기준으로 작업한다. 도구가 "changed on disk"라고 알리면 사용자가 바꾼 것으로 보고 되돌리지 않는다.
- 삭제는 영구 삭제 대신 **휴지통으로 이동**(되돌릴 수 있게). 사용자 본인 드래프트·원본은 건드리지 않는다. 사용자가 "기존 파일은 지워도 된다"고 명시한 경우에만 교체하되 이전본은 휴지통에 둔다.
- 파일을 이동·이름 변경하기 전에 다른 프로젝트(캡컷 draft 등)가 참조하는지 확인한다.
- 결과 폴더는 국가·언어별 하위 폴더를 만들지 말고 **파일명에 언어를 붙여 평평하게** 둔다. 소스는 `_소스`, 이전 버전은 `_이전버전`.

## 4. 문구·카피 규칙

**공통**
- 짧은 사실형, 차분한 어조. 금지: "5 days", 감사 표현을 억지로 넣는 것(단, 이벤트 마무리 인사는 사용자 지시로 사용), 괄호 남용, 억지 슬로건.
- 장식 이모지 최소화. 해시태그는 10개 내외, 검색어 중심.
- 번역은 직역 금지. 언어별 실제 사용 표현(검색어 포함)으로 쓴다.
- FR/JA는 번역가 검수가 필요하다고 **반드시** 알린다. 한국어 참고 번역을 함께 준다.
- 확실한 오타는 묻지 말고 바로 고친다(KO "MARTKET"→"MARKET").

**효능 표현(규제)**
- 일본·유럽·미국 모두 화장품 범위 안에서만. 금지/주의 표현: 혈행 개선, 흡수 촉진 단정, 회복·되살리는·재생, 자극 걱정 없이, 시술 후 피부, 완벽한, 피부 깊은 속까지, 극대화, 반영구, 카테킨 풍부, 식물 줄기세포, 미백·염증·재생(외국어판), "고함량"(소듐DNA 등), 비건·실리콘프리·무색소·무파라벤(유럽판은 무파라벤 삭제).

- 외국어판은 보르피린 +201%/+32% 같은 지방세포 관련 수치를 숨긴다.

**언어별**
- 일본어: 「ご連絡いたします」「お伺いします」 등 정중함 수준을 통일. 「当選者」「当選しました」 같은 표준 표현 사용. 자연스러움이 의심스러운 곳은 검수표에 ★.

## 5. 이미지·AI 생성 규칙 (Higgsfield 등)

**원칙**
- 제품 형태는 **실물 사진/원본 이미지를 참조**로 넣어 맞춘다. 글 설명만으로 생성하면 제품 형태(헤드, 링, 노즐, 뚜껑)가 틀어진다. 실물 참조가 없으면 사용자에게 요청.
- 결함은 영상이 아니라 **키프레임/원본에서 먼저** 고친다. 로컬 인페인팅·크롭으로 영상에서 지우면 얼룩덜룩해진다.
- 라벨 글자가 뭉개진 AI 이미지는 전체 재생성 대신 **제품별 크롭 + 실제 사진 참조로 재생성 → 정렬 → 라벨 영역만 합성**. 실제 라벨 사진은 `~/Desktop/이미지정리/<SKU>/학습용 실제 사진/`.
- 라벨 글자는 AI 글자가 아니라 실제 로고 파일/아트워크로 올리고, 곡면(병·튜브)은 원통 투영으로 감아 붙인다. 단색 덮기 대신 바탕 밝기에 곱하기.
- 확대·프레임 단위로 검수한 뒤 보고. 저해상도 시트만 보고 통과시키지 않는다.
- 사용자 업로드 이미지가 실제 사진/로고면 그것을 우선 쓴다. AI 생성은 원료·분위기 컷에 한정하고 행사·시험·채널 사진은 실물만.
- 생성물에 **제품 정체성이 어긋나면**(예: 이번 PDRN 세럼 뚜껑) 영상 전체를 다시 만들지 말고 **video_edit 모드**로 해당 부분만 고친다(움직임·조명 유지).
- AI가 만든 제품 렌더에서 **리프팅 크림의 분리형 LED 어플리케이터 헤드가 빠지는** 경향이 있다. 지적받은 적은 없지만 사실과 다르다. 사용자에게 알리고 필요하면 같은 방식으로 수정.

**Higgsfield 사용 메모**
- 이미지: `gpt_image_2_6`(quality high, resolution 2k, count 최대 4). 기존 사진 편집/참조는 `nano_banana_2_1`.
- 영상: `seedance_2_5`(mode `omni_reference`: 이미지 참조, `video_edit`: 영상 일부 수정, draft 480p → 확정 1080p). 확정 시 `draft_job_id`와 **원래 prompt·medias·duration·aspect_ratio를 다시 넣어야** 한다(프롬프트 비면 422). 과거 how-to 영상은 Kling 4.0 image-to-video(start+end 이미지).
- 음악: `elevenlabs_music_v2_5`(duration 필수, `force_instrumental`). 효과음 모델(mirelo)은 "game pipeline only"라 쓰지 못했다 → 효과음은 numpy로 직접 합성.
- 업로드: `media_upload` → 받은 URL로 `curl PUT`(Content-Type 맞춰서) → `media_confirm`. **큰 PNG는 520 오류**가 났다 → 1000px 정도로 줄여 재업로드. 이전 생성물은 `job_id`를 media value로 재사용 가능. 이미지 role은 선택 모델의 `medias[].roles`를 확인(Seedance: `start_image`, `image_references`, `video_references`; 서버가 start_image를 reference로 바꾸기도 함 → 결과가 첫 프레임과 다르면 프롬프트에 "첫 프레임에서 이어서"를 명시).
- 반드시 `get_cost`로 견적. 참고 비용: Kling 4.0 5초 720p ≈ 2.5, MiniMax 12.5, Seedance 2.5 720p 35 / 1080p 80~96(6초 기준), draft 약 18, video_edit 1080p 121, gpt_image_2_6 high 2k 3장 약 수 크레딧, 음악 28초×2 ≈ 8.
- 필터 오탐(nsfw): "손+붉은 LED" 같은 문구에서 발생 → 중립적으로 바꿔 재시도.
- 재희(DAMTIX AI 모델) 얼굴: `nano_banana_2_1`에 레퍼런스(정면 베이스 job `8471280d-…`, SoulID media `4239bf60-…`, **눈 클로즈업 `71939c89-…` 필수**)를 넣고 눈매(가로로 긴 아몬드형, 얇은 속쌍꺼풀, 윗눈꺼풀이 눈동자 윗부분을 덮음, 눈꼬리 길고 살짝 올라감, 차분한 눈빛, 짙은 갈색)를 글로 명시. 결과는 `이미지정리/<제품 폴더>`에 저장.
- 타인(인플루언서) 영상은 구도·순서 참고용. 가능하면 우리 자산으로 재생성.

## 6. 영상(릴스) 규칙

**릴스 공통**
- 규격 1080×1920, 30fps, H.264 High, yuv420p, 8~12Mbps 이하, `+faststart`, AAC 48kHz(음원 있을 때). 길이는 30초 이내 권장.
- **릴스에는 정지 이미지 금지**(사진을 줌/팬해서 쓰는 것도 금지). 릴스 컷은 실제 영상 소스만. 사진은 캐러셀·표지에만. (이번 당첨자 릴스의 제품 컷은 AI 영상 + HTML 모션 그래픽이며 사용자가 승인했다.)
- 릴스 UI 데드존: 상단 약 270px, 하단 약 1500px 아래는 피한다. 텍스트는 y 300~1480 안.
- 컷 후보 풀 먼저: 장면을 번호 붙인 짧은 후보 클립으로 뽑아 사용자 컨펌을 받고, 컨펌분만 재조립. 에이전트가 단독으로 "베스트 컷"을 고르지 않는다(기술 불량·얼굴·타사 노출만 표기).
- 방문객 얼굴은 크롭으로 제거하거나 아주 세게 블러(σ70). 타 브랜드/옆 부스 제품은 크롭으로 제외. 직원 얼굴·타사 노출은 사용자에게 알린다.
- 인파·분위기 컷은 초반, 같은 종류 연속 회피. 글자는 작게, 박스 없는 흰 볼드 타이틀 + 로고 문법(KDAY 릴스에서 사용자가 확정).

**16:9 영상을 릴스(9:16)로 바꿀 때 (JA how-to 사례)**
- 영상 비율을 변형하지 않는다(16:9 그대로). 위·아래 남는 영역은 **흰색**. 영상 밴드 1080×608을 세로 중앙(y 496~1104)에 두고 흰 프레임 오버레이(PNG, 투명 창)를 영상 트랙 위 세그먼트로 얹는다.
- 자막은 아래 흰 영역 y≈1262 중심, 데드존 회피. 글자는 차콜(#222).
- 자막이 **가로로 꽉 차거나 화면을 넘지 않게**: 폭이 화면의 약 52~58%를 넘지 않도록 수동 줄바꿈(캡컷 size 5.6, line_max_width 0.74). 일본어는 문절 단위로 줄바꿈.
- **행간은 기본값(0.02)이 너무 붙는다. 0.3 정도**(사용자 지적 "이런 기본 디테일은 알아서 해줘"). 줄 간격·여백 같은 기본 디테일은 처음부터 맞춘다.
- 한글 보조 자막: 일본어 아래 별도 텍스트 트랙, 회색(#999), Pretendard, 크기 5(사용자 지정 — 3.2는 "너무 작다"), 일본어 줄 수에 맞춰 위치 계산, 긴 문장은 의미 단위 줄바꿈.
- 더빙: ElevenLabs(Higgsfield `elevenlabs_v4`)로 일본어 더빙을 클립별로 만들고(앞뒤 무음 제거, atempo 1.0~1.25로 길이 맞춤), 캡컷에 클립별 오디오 8개로 넣어 사용자가 수정 가능하게. 더빙은 자막보다 축약될 수 있다는 점을 사용자에게 알린다. 음악은 볼륨을 낮추고(0.32) 더빙을 위로.
- 영상 제작 시 **캡컷 draft도 함께** 만들어 사용자가 직접 수정할 수 있게 한다(mp4만 주지 않는다). 글자를 mp4에 굽지 않고 캡컷 네이티브 텍스트 레이어로.

**캡컷(CapCut 9.6) 작업 절차**
- draft 경로 `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/`. 캡컷이 실행 중이면 저장 때 덮어쓰므로 **완전 종료**(`osascript quit`은 -128 오류가 나도 종료됨, `pgrep -x CapCut`으로 확인) → 백업 → 파일 수정 → 재실행. 새 draft는 종료 상태에서 `root_meta_info.json`에 등록.
- draft 내용은 평문 JSON이다. 같은 내용을 6개 파일에 모두 기록: 루트 `draft_info.json`, `.bak`, `template-2.tmp`와 `Timelines/<id>/` 아래 같은 3개.
- 크기는 추정하지 말고 캡컷 화면으로 확인(1920×1080에서 size 1 ≈ 9.5px, 1080폭 세로 캔버스에서 size 1 ≈ 6.24px). 세로 캔버스 값으로 가로 캔버스를 환산하면 틀린다.
- 캡컷이 계속 열려 있고 사용자가 입력 중이면 UI 자동 클릭이 막힌다("사용자가 입력 중"). 강제로 우회하지 말고, 해야 할 UI 단계(열기, 내보내기)는 사용자에게 방법을 알려 준다.
- 사용자가 편집한 draft(예: v2의 컷 타이밍)는 읽어서 그 상태를 기준으로 삼는다. 복제할 때는 새 UUID, 미디어 경로 유지(이동·이름 변경 금지).

**HTML 모션 그래픽 파이프라인(이번 당첨자 릴스)**
- `scene.html`에 `render(t)` 함수를 두고 모든 요소를 시간 함수로 계산(결정적). puppeteer-core + Google Chrome으로 프레임을 PNG로 캡처(`render.mjs`), ffmpeg로 합성. 투명 오버레이는 `omitBackground`.
- 전환 타이밍은 `u = t + 오프셋`으로 한 곳에서 조정. 문구·위치·크기는 숫자만 바꿔 다시 렌더.
- 크롬 제품 컷은 AI 영상(가챠 기계 → 캡슐 → 제품 튀어나옴) + 실제 제품 컷아웃. 영상 안 흰 카드 문구(추첨 결과 안내)는 기계가 화면을 채우므로 **흰 카드 위에** 올린다.

**오디오**
- 음악: 보컬 없는 인스트루멘털. 영상의 전환점(당첨자 발표 시작)에 에너지가 오르도록 프롬프트를 쓰고, 파형·구간 RMS로 확인. 곡 길이가 영상보다 짧으면 끝 페이드와 효과음으로 메운다.
- 효과음: 합성(`_소스/sfx.py`). 클릭·팝·벨·휘슉 등을 영상 타임라인 초에 맞춰 배치하고 좌우 패닝. 이벤트 시각은 영상 프레임을 5fps로 뽑아 확인해서 정한다.
- 라우드니스: 본편 약 −14.6 LUFS, 최대 −0.5 dBFS(AAC 인코딩 후 인터샘플 피크가 0을 넘기 쉬우니 limiter와 볼륨을 낮춰 확인). 효과음만 버전도 함께 낸다(인스타 앱에서 음악을 직접 고를 때 사용).
- 음악 라이선스: AI 생성 음악의 상업 이용은 Higgsfield/ElevenLabs 약관·플랜을 사용자가 확인해야 한다. 비즈니스 계정은 인스타의 상업용 음원만 쓸 수 있다는 점도 알린다. 직접 듣지 못했다면 못 들었다고 쓴다.

**내보내기·최적화**
- 인스타용: `scale 1080:1920, fps 30, yuv420p`, libx264 high profile level 4.2 crf 17 maxrate 12M bufsize 24M, AAC 192k 48kHz, `-movflags +faststart`, bt709 태그.
- 웹용 원본 보존 + `_web.mp4`(1080p CRF 23 slow, AAC 128k) 규칙은 how-to 영상에서 사용.
- 캡컷에서 내보내기: 1080p, 30fps, H.264, mp4, 비트레이트 높음 → 이후 ffmpeg로 인스타 규격 후처리(`finalize_ig.sh`).

## 7. 캐러셀·이미지 규칙

- 규격 **1080×1350(4:5)**. 파일명 `DAMTIX_IG_{LANG}_{NN}_{name}`. 스토리는 1080×1920.
- 이미지 속 글자는 최소화. 표지·매장·내부 장에는 아주 작은 한 줄만. 위치는 "인천공항 제1·2터미널 시티면세점"까지만(매장 번호·게이트 지어내지 않음).
- 표지는 같은 이벤트 영상과 같은 분위기여야 한다(영상 프레임을 먼저 보고 문법을 읽는다). 제품은 실제 제품이 크게 보이게, 얼굴은 크롭으로 제거.
- 중앙정렬은 **이미지 상자가 아니라 시각적 본체 기준**으로 맞춘다. 어플리케이터가 한쪽에 붙은 크림은 용기 본체 중심을 이름 글자 중심에 맞추고, 두 제품은 같은 세로 중심선에 놓는다(좌우 칼럼 중심은 슬라이드 중심 ±대칭).
- 크기 관계: 사용자가 "세럼이 너무 크다" → 3/5로 줄였다가 "너무 작다" → 약 72%로 되돌렸다. 같은 줄의 제품은 시각적 비중을 사용자 판단으로 맞추고, 지시된 비율만 정확히 적용.
- 영상이 캐러셀 1번이면 영상 마지막 장면에 "오른쪽으로 넘기면 이미지로도 확인"을 안내하고(화살표 포함), 캡션 앞부분에도 같은 안내를 넣는다.
- 캡션 구성: 한 줄 헤드라인 → 핵심 내용 → 위치/기한 등 팩트 → 안내 → 프로필 링크 안내(필요 시) → 해시태그 약 10개. 한국어 참고 번역 파일과 검수표를 함께.
- 웹에 올리는 이미지는 **WebP 등 웹용 변환본**(7장 아래 SEO 참고). Figma에 올릴 때 **WebP는 렌더가 비는 경우가 있어 JPEG/PNG로 변환**해서 올린다(이번에 WebP 업로드가 빈 회색으로 나왔다).

## 8. Figma 카탈로그 규칙 (파일 `vO27aSlfoB1BUE16iB8CTi`, 담틱스 카탈로그 리뉴얼)

## 12. 자주 난 실수와 교훈 (체크리스트)

1. 저해상도 시트만 보고 "고쳤다"고 보고 → 확대·프레임 단위로 확인.
2. 경로를 줄여 알림 → 전체 경로.
3. 사용자가 편집한 draft/파일을 재생성 → 금지. 읽어서 이어서 작업.
4. 캡컷 실행 중 draft 수정 → 저장 때 덮어씀. 종료 후 수정.
5. 캡컷 크기를 추정 → 화면으로 확인(캔버스별 px/size 다름).
6. 자막이 꽉 차거나 넘침 → 폭 52~58% 이하, 수동 줄바꿈.
7. 행간 기본값(0.02) → 0.3. 기본 디테일은 말하기 전에 맞춘다.
8. 제품 형태·라벨을 글로만 설명해 생성 → 실물 참조. PDRN 세럼 뚜껑(흰 볼 금지), 아이크림(전체 크롬), 크림 LED 헤드 누락.
9. 영상에서 결함을 로컬로 지움 → 키프레임/video_edit로 수정.
10. 사용자가 비워 둔 질문에 되묻기 → 추천안으로 결정.
11. 일본어 자연스러움을 사용자에게 물음 → AI가 정하고 검수표로 원어민에게.
12. 효능 단정·금지어 사용 → 4장 목록 점검.
13. 참가자 수·추첨 도구명·giveaway 표현·주소 문구를 영상에 노출 → 모두 금지.
14. 크림 이미지를 이미지 상자 중심으로 정렬 → 본체 중심 기준.
15. Figma에서 큰 응답 요청 → 20KB 초과 시 SSE 오류. 작게 나눠 읽기.
16. WebP를 Figma에 올림 → 빈 이미지. JPEG/PNG로.

## 14. 인수받은 AI의 첫 행동

1. 이 문서 1·2장과 12장을 읽는다.
2. 사용자의 요청에 해당하는 장(3~9)을 읽고, **해당 프로젝트 폴더·파일을 직접 열어 현재 상태를 확인**한다. 사용자가 편집했을 수 있다.
3. 큰 작업이면 기획부터 설명하고 승인을 받는다. 작은 수정이면 요청 범위만 바꾼다.
4. 일본어·프랑스어 문구가 들어가면 검수표를 같이 만든다.
5. 만든 뒤 확대·프레임 단위로 직접 확인하고, 확인하지 못한 것은 못 했다고 쓴다.
6. 보고는 한국어로 짧게: 무엇을 어디에(전체 경로) 만들었는지, 사용자가 확인할 점, 크레딧 사용량. 게시는 하지 않는다.
